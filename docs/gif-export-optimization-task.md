# GIF 导出交互优化任务

## 目标

优化徽章 GIF 导出的操作流程，使用户可以明确配置、取消、重试和下载，并降低长时间生成时的误操作。默认帧间隔调整为 **0.4 秒（400 ms）**。

## 帧间隔方案

采用“统一帧间隔 + 少量常用档位”的逻辑：所有帧使用同一间隔，避免轮播节奏不一致，也便于用户预估 GIF 总时长。

| 档位 | 间隔 | 适用场景 |
| --- | ---: | --- |
| 快速（默认） | 400 ms | 徽章轮播、快速浏览 |
| 标准 | 600 ms | 通用展示 |
| 慢速 | 800 ms | 需要看清细节 |
| 展示 | 1200 ms | 分享或演示 |
| 逐帧 | 2000 ms | 仔细查看单枚徽章 |

实现约束：

- 默认值由 `800` 改为 `400`；
- 间隔统一限制在 `200–2000 ms`；
- 输入值规范化为 10 ms 的整数倍，匹配 GIF 时间精度；
- 生成前显示预计时长：`帧数 × 间隔`，例如 `8 帧 · 3.2 秒`；
- 暂不采用首帧停留更久或每帧不同间隔，避免增加理解和测试成本。

## 优先级任务

### P0：必须完成

- [ ] 增加“取消生成”操作，取消后停止后续编码和网络加载，并恢复可编辑状态。
- [ ] 生成期间锁定排序、删除、间隔选择和生成按钮，避免配置与任务不一致。
- [ ] 将默认间隔改为 400 ms，并更新相关测试和文案。
- [ ] 生成失败时保留当前排序、帧数和间隔，提供“重试”。
- [ ] 生成前校验帧数（至少 2 帧，最多建议 12 帧），给出明确原因。

### P1：建议完成

- [ ] 生成前显示帧数、间隔和预计总时长。
- [ ] 生成成功后保留预览，提供“下载”“重新生成”“调整参数”。
- [ ] 关闭弹窗时若仍在生成，提示取消或继续生成；取消后释放任务资源。
- [ ] 移动端以左右移动按钮作为主要排序方式，拖拽作为增强操作。
- [ ] 进度显示包含重编码阶段，例如“第 2 次编码（128 色）”。

### P2：性能和体验优化

- [ ] 将 GIF 编码移入 Web Worker，避免量化过程阻塞页面。
- [ ] 释放图片 Blob URL，并为图片缓存增加上限或清理策略。
- [ ] 参数变更时保留旧预览，仅标记“配置已变更”，由用户确认重新生成。
- [ ] 增加无障碍键盘排序和取消操作。

## 事件和状态建议

状态建议统一为：`idle`、`generating`、`success`、`error`、`cancelled`。

- `idle → generating`：通过校验后开始生成；记录本次配置快照。
- `generating → cancelled`：用户主动取消或弹窗关闭并确认取消。
- `generating → success`：仅当任务 ID 与当前任务一致时接受结果。
- `generating → error`：保留配置快照，允许重试。
- 排序、删除或修改间隔时，不直接执行生成；标记配置变化并使旧结果失效。

建议使用 `AbortController` 取消 fetch，并在编码循环中检查 `signal.aborted`。任务 ID 仍应保留，用于防止旧任务结果覆盖新任务。

## 验证方式

### 自动化验证

- [ ] 单元测试：默认间隔为 400 ms，档位值正确，输入会被限制并按 10 ms 取整。
- [ ] 单元测试：帧数少于 2 或超过上限时阻止生成。
- [ ] 单元测试：取消后不会更新成功结果，也不会触发下载 URL 创建。
- [ ] 单元测试：旧任务完成时不会覆盖新任务状态。
- [ ] 组件测试：生成期间操作控件为禁用状态；失败后“重试”保留原配置。
- [ ] 运行 `pnpm typecheck`、`pnpm lint` 和 `pnpm test`。

### 手工验收

- [ ] 选择 2、8、12 帧，确认预计时长分别为 `0.8s`、`3.2s`、`4.8s`。
- [ ] 在生成过程中取消，确认页面恢复可操作且没有生成结果残留。
- [ ] 生成过程中尝试排序、删除和修改间隔，确认不会改变当前任务配置。
- [ ] 模拟图标加载失败，确认错误包含徽章名称且可以重试。
- [ ] 在桌面端和移动端分别验证排序、预览、下载和关闭行为。

## 完成标准

P0 项全部通过自动化和手工验证后，方可合入；P1 可作为同一迭代的体验改进，P2 根据实际编码耗时和低端设备表现安排。

## 切换效果选项

切换效果建议采用“效果 + 间隔”两个独立配置。间隔表示每个徽章完整展示的时间，过渡时间从间隔中扣除，避免选择效果后整体播放速度变慢。

### 推荐效果

| 效果 | 默认过渡时长 | 表现 | 实现成本 | 优先级 |
| --- | ---: | --- | --- | --- |
| 直接切换 | 0 ms | 当前徽章消失，下一枚立即出现 | 低 | P0 |
| 淡入淡出 | 160 ms | 当前徽章淡出，下一枚淡入 | 中 | P1 |
| 缩放切换 | 200 ms | 当前徽章轻微缩小，下一枚放大到正常尺寸 | 中 | P1 |
| 左右滑动 | 220 ms | 当前徽章向左移出，下一枚从右侧进入 | 中 | P1 |
| 上下滑动 | 220 ms | 当前徽章向上移出，下一枚从下方进入 | 中 | P2 |
| 翻页 | 260 ms | 像卡片翻页一样切换 | 高 | P2 |

首版建议只上线：**直接切换、淡入淡出、缩放切换、左右滑动**。这四种效果覆盖无动画、柔和、强调主体和方向感四类需求，且不会让设置面板过于复杂。

### 统一参数规则

- 默认效果为“直接切换”，默认间隔为 400 ms；
- 过渡时长固定为间隔的 25% 或不超过 220 ms，避免 400 ms 快速轮播被过渡动画占满；
- 最小间隔为 200 ms；当间隔小于 800 ms 时，过渡时长不得超过间隔的 40%；
- 过渡期间使用逐帧采样，建议每个过渡生成 4–8 帧；
- 所有帧使用白色背景，避免 GIF 透明色在不同播放器中产生边缘问题；
- GIF 无限循环时，最后一枚到第一枚也使用同一种过渡效果。

### 操作逻辑

- 在间隔设置旁增加“切换效果”单选项，并使用小型实时预览；
- 切换效果变更只影响待生成配置，不自动重新编码；
- 生成前显示摘要，例如：`8 帧 · 每帧 0.4 秒 · 淡入淡出 · 总时长约 3.2 秒`；
- 生成期间锁定效果、间隔和排序；
- 生成失败后保留效果选择，支持直接重试；
- 记住用户上次选择的效果，但首次使用仍采用直接切换，避免突然增加编码耗时。

### 实现建议

- 把每个徽章视为一个独立的 `Frame`，由效果函数生成从当前帧到下一帧的中间帧；
- 统一接口：`renderTransition(from, to, progress, effect)`，其中 `progress` 范围为 `0..1`；
- 直接切换只生成目标帧，其他效果通过 Canvas 合成中间帧后再交给 GIF 编码器；
- 对淡入淡出使用 alpha 合成，对滑动和缩放使用变换矩阵；
- 不建议首版实现真正的 3D 翻页，Canvas 近似效果在不同浏览器上容易产生锯齿和边缘差异。

### 效果验收

- [ ] 每种效果都能在生成前通过预览明确区分；
- [ ] 400 ms 间隔下，过渡不会导致徽章无法辨认；
- [ ] 最后一帧切回第一帧时无明显停顿或闪烁；
- [ ] 2、8、12 帧下总时长与摘要一致，误差不超过一个 GIF 时间单位（10 ms）；
- [ ] 各效果生成结果可在 Chrome、Safari、Firefox 和常见图片查看器中正常循环播放；
- [ ] 开启效果后仍遵守 10 MB 文件大小限制，超限时按既有降色阶策略处理；
- [ ] 低端设备上生成期间页面仍可取消，取消后不会产生下载结果。

## 小图标选择、大图标生成

徽章同时提供两套资源：

- 小图标：`https://r2.2libra.com/badge/svg/{id}.svg`，用于选择列表、排序列表和生成前预览；
- 大图标：`https://r2.2libra.com/badge/{id}.svg`，用于 Canvas 绘制和最终 GIF 编码。

同时允许用户选择“纯小图标生成”。该模式直接使用小图标编码，适合快速生成、网络较慢或用户希望保持列表图标视觉效果的场景。

以 `listen_to_me` 为例：

```text
小图标 https://r2.2libra.com/badge/svg/listen_to_me.svg
大图标 https://r2.2libra.com/badge/listen_to_me.svg
```

### 数据模型

徽章对象建议显式区分两个地址，避免在多个组件中拼接 URL：

```ts
interface BadgeRecord {
  id: string
  name: string
  icon: string       // 小图标，列表和弹窗展示
  exportIcon: string // 大图标，仅 GIF 生成使用
}
```

如果现有数据只有 `icon`，可在数据转换层统一补齐：

```ts
const BADGE_ASSET_BASE = 'https://r2.2libra.com/badge'
const BADGE_SMALL_ASSET_BASE = `${BADGE_ASSET_BASE}/svg`

function toBadgeAssets(id: string) {
  return {
    icon: `${BADGE_SMALL_ASSET_BASE}/${encodeURIComponent(id)}.svg`,
    exportIcon: `${BADGE_ASSET_BASE}/${encodeURIComponent(id)}.svg`,
  }
}
```

### 操作逻辑

- 勾选、排序、移除和生成前预览全部使用小图标，减少列表加载体积；
- 在生成设置中增加“生成图标”选项：`高清大图标（默认）`、`使用小图标`；
- 选择“高清大图标”后，按当前顺序加载对应大图标；
- 选择“使用小图标”后，只加载并编码小图标，不再请求大图标；
- 高清大图标加载失败时，不自动切换到小图标，应显示徽章名称并允许用户主动切换模式或重试；
- 小图标加载失败只影响界面预览，可显示占位图，但不能改变最终生成资源；
- 生成期间不重复加载同一来源的图标，大小图标缓存彼此隔离；
- 生成摘要中明确标注资源来源，例如：`8 帧 · 0.4 秒 · 淡入淡出 · 高清大图标`；
- 纯小图标模式显示提示：`文件更小、生成更快，但清晰度取决于小图标尺寸`。

### 配置模型

```ts
type GifIconSource = 'large' | 'small'

interface GifMakerOptions {
  delayMs: number
  effect: GifEffect
  iconSource: GifIconSource
}
```

`iconSource` 必须记录在本次任务配置快照中。任务开始后不能切换，避免同一个 GIF 混合使用两套资源。

### 兼容和安全约束

- `id` 只能匹配现有徽章 ID 规则，URL 必须使用 `encodeURIComponent`；
- Worker 代理接口同时支持 `size=small|large`，服务端根据白名单拼接路径，禁止客户端传入任意 URL；
- 直连 R2 失败时，大图标和小图标分别走同源代理；
- 代理响应校验 `Content-Type: image/svg+xml`，并设置 `X-Content-Type-Options: nosniff`；
- 大图标和小图标分别缓存，避免用小图标响应污染大图标缓存。

### 验收方式

- [ ] 列表和排序区域请求的是 `/badge/svg/{id}.svg`；
- [ ] GIF 编码请求的是 `/badge/{id}.svg`；
- [ ] 选择“高清大图标”时 GIF 编码请求的是 `/badge/{id}.svg`；
- [ ] 选择“使用小图标”时 GIF 编码只请求 `/badge/svg/{id}.svg`，不请求大图标；
- [ ] `listen_to_me` 等同一 ID 的两套资源不会混用；
- [ ] 小图标请求失败时列表仍可操作；
- [ ] 大图标请求失败时生成被阻止，并提示具体徽章名称；
- [ ] R2 直连失败后，大小图标都能正确切换到同源代理；
- [ ] 网络面板确认没有为同一徽章重复下载大图标；
- [ ] 高清大图标模式的生成结果使用大图标清晰度，不能静默退回小图标。
- [ ] 纯小图标模式生成结果与列表中的小图标视觉一致；
- [ ] 切换图标来源后，旧预览被标记为失效，不会被误下载；
- [ ] 默认仍为高清大图标，用户主动选择后才使用纯小图标。
